# Свод правил разработки ПО управления PMSM

Документ основан на анализе прошивки VESC (Benjamin Vedder). Содержит критические правила
и рекомендации для разработки собственного FOC-контроллера на STM32G431.

---

## 1. Безопасность трёхфазного инвертора

### 1.1 Мёртвое время (Dead Time)

Мёртвое время — обязательный параметр, без него верхний и нижний ключи одного плеча
открываются одновременно → сквозной ток → мгновенный выход из строя силовых транзисторов.

**Правило:** мёртвое время задаётся аппаратно в регистре TIM_BDTR.DTG на основе тактовой
частоты ядра. В VESC используется макрос `conf_general_calculate_deadtime(HW_DEAD_TIME_NSEC, SYSTEM_CORE_CLOCK)`.
Значение выбирается по datasheet драйвера затворов (для STM32G431 / STDRIVEG600 типовое значение — 100–300 нс).

```c
TIM_BDTRInitStructure.TIM_DeadTime = conf_general_calculate_deadtime(HW_DEAD_TIME_NSEC, SYSTEM_CORE_CLOCK);
```

### 1.2 Безопасное состояние PWM

В **любой** аварийной ситуации единственным безопасным состоянием является **отключение всех
силовых ключей** (High-Z). Перевод верхних ключей в LOW при открытых нижних (Full Brake)
допустим только при контролируемом торможении.

Алгоритм `stop_pwm_hw()` из VESC:

1. Обнулить уставки тока: `m_id_set = 0`, `m_iq_set = 0`
2. Для каждого канала TIM: `TIM_SelectOCxM(TIM, CH, TIM_ForcedAction_InActive)` — GPIO в неактивное состояние
3. Верхний ключ: `TIM_CCxCmd — Enable` (но неактивен), нижний: `TIM_CCxNCmd — Disable`
4. Сгенерировать COM-событие: `TIM_GenerateEvent(TIM, TIM_EventSource_COM)` — немедленное применение
5. Установить флаг: `motor->m_pwm_mode = FOC_PWM_DISABLED`

**Критично:** COM-событие (`TIM_EventSource_COM`) применяет изменения режима OCxM атомарно и
немедленно, не дожидаясь UEV. Без этого вызова изменения вступят в силу только на следующем
обновлении таймера.

### 1.3 Аппаратная защита BRK

STM32 поддерживает вход BRK (Break Input) у таймеров TIM1/TIM8. При срабатывании BRK
все PWM-выходы аппаратно переходят в безопасное состояние **асинхронно**, без участия CPU —
это защищает плату даже при зависшем микроконтроллере.

```c
// В VESC (при HW_USE_BRK):
TIM_BDTRInitStructure.TIM_Break = TIM_Break_Enable;
TIM_BDTRInitStructure.TIM_BreakPolarity = TIM_BreakPolarity_Low; // или High — по схеме
TIM_BDTRInitStructure.TIM_AutomaticOutput = TIM_AutomaticOutput_Disable;
// AutomaticOutput_Disable: после снятия BRK PWM не восстанавливается автоматически.
// Восстановление только программное — это важно для контроля.
```

**Правило:** использовать BRK при наличии аппаратного сигнала аварии от драйвера затворов.
Устанавливать `TIM_AutomaticOutput_Disable` — автоматическое восстановление PWM после снятия
аварии недопустимо без анализа причины.

### 1.4 Full Brake (активное торможение замыканием фаз)

`full_brake_hw()` замыкает все нижние ключи (все фазы на GND). Создаёт тормозной момент
за счёт рекуперативных токов. Применяется при малых скоростях. При высоких оборотах
генерирует большие токи — нужен контроль.

**Правило:** Full Brake применять только при `|RPM| < L_CURR_MAX_RPM_FBRAKE`, иначе
использовать регулируемый тормозной ток.

## 2. Архитектура FOC-управления

### 2.1 Структура данных состояния мотора

Всё состояние мотора хранится в одной структуре `motor_all_state_t`. Глобальный экземпляр —
`m_motor_1` (и `m_motor_2` при двойном моторе). Доступ через геттер-указатель.

Ключевые поля `motor_state_t` (вложенное `m_motor_state`):

| Поле | Описание |
|---|---|
| `i_alpha`, `i_beta` | Токи Кларка (αβ) |
| `id`, `iq` | Токи d/q (парк) |
| `vd`, `vq` | Напряжения d/q от PI |
| `mod_alpha_raw`, `mod_beta_raw` | Модуляция SVM (αβ) |
| `phase` | Угол ротора (рад), используемый для управления |
| `v_bus` | Напряжение шины (В) |
| `duty_now` | Текущий скважностный цикл |

Поля `motor_all_state_t`:

| Поле | Описание |
|---|---|
| `m_phase_now_observer` | Угол от наблюдателя |
| `m_phase_now_encoder` | Угол от энкодера |
| `m_pll_speed` | Скорость от PLL (рад/с) |
| `m_observer_state` | Состояние наблюдателя: `x1`, `x2`, `lambda_est` |
| `m_hfi` | Состояние HFI-инжекции |
| `m_pwm_mode` | `FOC_PWM_DISABLED` / `FOC_PWM_ENABLED` / `FOC_PWM_FULL_BRAKE` |

### 2.2 Главный цикл управления (ADC ISR)

Цикл FOC выполняется в прерывании ADC с частотой дискретизации (обычно 10–40 кГц):

```
ADC ISR → mcpwm_foc_adc_int_handler()
  1. Считать значения АЦП (токи фаз, напряжение шины)
  2. Вычесть DC-смещения (m_curr0_offset, m_curr1_offset, m_curr2_offset)
  3. Преобразование Кларка: (Ia, Ib, Ic) → (i_alpha, i_beta)
  4. Получить угол ротора (энкодер / наблюдатель / HFI)
  5. Преобразование Парка: (i_alpha, i_beta, θ) → (id, iq)
  6. PI-регуляторы тока: id → vd, iq → vq
  7. Обратное преобразование Парка: (vd, vq, θ) → (v_alpha, v_beta)
  8. SVM: (v_alpha, v_beta) → (CCR1, CCR2, CCR3)
  9. Атомарно обновить CCR: UDIS → set CCR → ~UDIS
 10. Обновить наблюдатель (foc_observer_update)
 11. timeout_feed_WDT(THREAD_MCPWM)
```

### 2.3 Атомарное обновление CCR

Чтобы не обновлять CCR частично (что привело бы к асимметрии фаз на один период PWM),
все три регистра обновляются одним блоком с отключённым UEV:

```c
TIM1->CR1 |= TIM_CR1_UDIS;   // запретить UEV — значения не защёлкнутся до сброса
TIM1->CCR1 = duty1;
TIM1->CCR2 = duty2;
TIM1->CCR3 = duty3;
TIM1->CR1 &= ~TIM_CR1_UDIS;  // разрешить UEV — все три значения защёлкнутся вместе
```

### 2.4 Частота переключения (центрально-симметричный PWM)

TIM1/TIM8 работают в режиме `TIM_CounterMode_CenterAligned1` (up-down). Период задаётся:

```
TIM_Period = SYSTEM_CORE_CLOCK / f_zv
```

где `f_zv` — удвоенная частота переключения (т.к. up-down). При `f_zv = 40000` и ядре
170 МГц: `TIM_ARR = 4250`. Частота ADC ISR равна частоте переключения.

## 3. DC-калибровка смещений АЦП

### 3.1 Назначение

Операционные усилители токовых шунтов имеют ненулевое смещение постоянного тока (offset).
Если не компенсировать, FOC будет управлять с постоянно добавленным «фантомным» током,
что вызывает нагрев мотора и ошибки регулирования.

### 3.2 Процедура калибровки

Вызывать `mcpwm_foc_dc_cal()` при старте, **до** начала вращения, при PWM = 0:

1. Выключить PWM: `stop_pwm_hw()`
2. Включить DC CAL pin: `DCCAL_ON()` (подключает входы ОУ к нулевому опорному напряжению)
3. Подождать стабилизации: `chThdSleepMilliseconds(1000)`
4. Усреднить несколько тысяч отсчётов АЦП для каждого канала
5. Сохранить смещения: `m_curr0_offset`, `m_curr1_offset`, `m_curr2_offset`
6. Выключить DC CAL pin: `DCCAL_OFF()`
7. Установить: `m_dccal_done = true`

**Правило:** никогда не управлять мотором пока `!mcpwm_foc_is_dccal_done()`. Проверять флаг
перед первой подачей тока.

### 3.3 Контроль качества калибровки

После калибровки: если `|offset| > FAULT_THRESHOLD_HIGH_OFFSET_CURRENT` — генерировать
`FAULT_CODE_HIGH_OFFSET_CURRENT_SENSOR_x`. В VESC порог — ~0.5·VCC/2 ADC kодов.

## 4. Режимы управления PWM

### 4.1 Рекомендуемый режим — синхронный (Synchronous)

```c
// PWM_MODE_SYNCHRONOUS — оба ключа (верх/низ) управляются активно.
// Это обеспечивает рекуперацию и наилучшее качество тока.
```

- `PWM_MODE_NONSYNCHRONOUS_HISW` — нижний ключ никогда не открывается принудительно,
  нет рекуперации, не рекомендован VESC.
- `PWM_MODE_BIPOLAR` — возможны глитчи, может уничтожить MOSFET. Не использовать.

### 4.2 Минимальный и максимальный duty cycle

```c
#define MCCONF_L_MIN_DUTY   0.005   // 0.5% — ниже неустойчивое детектирование тока
#define MCCONF_L_MAX_DUTY   0.95    // 95%  — запас на dead time и drop напряжения
```

При duty < MIN: переходить в `MC_STATE_OFF` (stop_pwm_hw). При duty > MAX: клипировать.

## 5. Оценка положения ротора

### 5.1 Режимы датчиков

| Режим | Описание | Применение |
|---|---|---|
| `FOC_SENSOR_MODE_SENSORLESS` | Наблюдатель потокосцепления | Средние/высокие скорости |
| `FOC_SENSOR_MODE_ENCODER` | АМЕ/AS5600 | Весь диапазон скоростей |
| `FOC_SENSOR_MODE_HALL` | Датчики Холла | Грубое позиционирование |
| `FOC_SENSOR_MODE_HFI` | Инжекция ВЧ-сигнала | Старт и малые скорости |
| `FOC_SENSOR_MODE_HFI_START` | HFI только для старта | Гибридный режим |

### 5.2 Наблюдатель потокосцепления

Состояние наблюдателя — структура `observer_state`:

```c
typedef struct {
    float x1;           // оценка потокосцепления по α
    float x2;           // оценка потокосцепления по β
    float lambda_est;   // оценка модуля потокосцепления
    float i_alpha_last;
    float i_beta_last;
} observer_state;
```

Вызов: `foc_observer_update(v_alpha, v_beta, i_alpha, i_beta, dt, &state, &phase, motor)`

Доступные типы: `FOC_OBSERVER_ORTEGA_ORIGINAL`, `FOC_OBSERVER_MXLEMMING`,
`FOC_OBSERVER_ORTEGA_LAMBDA_COMP`, `FOC_OBSERVER_MXLEMMING_LAMBDA_COMP`,
`FOC_OBSERVER_MXV`, `FOC_OBSERVER_MXV_LAMBDA_COMP`.

Параметр наблюдателя: `foc_observer_gain` — усиление. Чем выше — тем быстрее реакция,
но выше чувствительность к шуму.

### 5.3 Приоритет источника угла

Функция `foc_correct_encoder()` выбирает угол в зависимости от скорости:

- При `|speed_erpm| < sl_erpm`: использовать угол энкодера
- При `|speed_erpm| > sl_erpm`: использовать угол наблюдателя (более точный на высоких скоростях)

Для AS5600 (I2C, 12-бит, 360°): погрешность ≈ 0.088°. Calibration offset получается через
`mcpwm_foc_encoder_detect()` — вращение с малым открытым контуром, усреднение смещения
между электрическим и механическим углом.

### 5.4 PLL для оценки скорости

```c
foc_pll_run(phase, dt, &motor->m_pll_phase, &motor->m_pll_speed, conf);
```

PLL даёт гладкую оценку скорости без дифференцирования угла. Параметры:
`foc_pll_kp`, `foc_pll_ki` в конфигурации.

## 6. Текущие контроллеры (PI)

### 6.1 Структура

Для каждого из токов id, iq — независимый PI с anti-windup:

```
error = id_ref - id_measured
vd = Kp * error + integral_d
integral_d += Ki * error * dt  (clamp to [vd_min, vd_max])
```

### 6.2 Развязка (Decoupling)

При высоких скоростях id и iq взаимно индуктивно связаны. Необходима явная компенсация:

- `FOC_CC_DECOUPLING_CROSS` — компенсация перекрёстных связей: `vd -= ω·Lq·iq`
- `FOC_CC_DECOUPLING_BEMF` — компенсация BEMF: `vq += ω·λ`
- `FOC_CC_DECOUPLING_CROSS_BEMF` — оба одновременно (рекомендуется)

### 6.3 Ограничения напряжения

Максимальное фазное напряжение ограничено шиной: `|V_dq| ≤ V_bus · max_duty / √3`.
Используется клипирование с сохранением угла вектора напряжения.

## 7. SVM (Space Vector Modulation)

```c
foc_svm(alpha, beta, max_mod, PWMFullDutyCycle, &tA, &tB, &tC, &sector);
```

- `max_mod` — максимальная глубина модуляции (0.95 типично)
- `PWMFullDutyCycle` = TIM_ARR
- Возвращает `tA`, `tB`, `tC` — значения для CCR1, CCR2, CCR3
- `svm_sector` — номер сектора (1–6), используется для выбора точки замера тока

**Точка замера тока:** В центрально-симметричном PWM ток измеряется в момент, когда все
нижние ключи открыты (нулевой вектор V0 в центре периода). TIM2->CCR2 задаёт задержку
относительно пика/впадины TIM1.

## 8. Ограничения и защиты

### 8.1 Токовые защиты

| Параметр | Значение по умолчанию | Действие при превышении |
|---|---|---|
| `L_CURRENT_MAX` | 60 А | Ограничение тока q |
| `L_MAX_ABS_CURRENT` | 130 А | `FAULT_CODE_ABS_OVER_CURRENT`, stop_pwm |
| `L_IN_CURRENT_MAX` | 99 А | Ограничение входного тока |
| Дисбаланс токов фаз | `UNBALANCED_CURRENT_LIMIT` | `FAULT_CODE_UNBALANCED_CURRENTS` |
| High offset sensor | `HIGH_OFFSET_LIMIT` | `FAULT_CODE_HIGH_OFFSET_CURRENT_SENSOR_x` |

### 8.2 Напряжение шины

| Параметр | Значение | Действие |
|---|---|---|
| `L_MAX_VOLTAGE` | 57 В | `FAULT_CODE_OVER_VOLTAGE` |
| `L_MIN_VOLTAGE` | 8 В | `FAULT_CODE_UNDER_VOLTAGE` |
| `L_BATTERY_CUT_START` | 10 В | Начало ограничения тока |
| `L_BATTERY_CUT_END` | 8 В | Полное отключение тока |

### 8.3 Температурные защиты

- `L_LIM_TEMP_FET_START = 85°C` — начало линейного снижения тока
- `L_LIM_TEMP_FET_END = 100°C` — полное отключение (`FAULT_CODE_OVER_TEMP_FET`)
- `L_LIM_TEMP_MOTOR_START/END` — аналогично для обмоток (`FAULT_CODE_OVER_TEMP_MOTOR`)

### 8.4 Коды неисправностей

Все коды — `mc_fault_code`. При любом fault кроме `FAULT_CODE_NONE`:

1. Вызвать `stop_pwm_hw()` немедленно
2. Запомнить код неисправности
3. Передать задаче обработки аварий (высокий приоритет)
4. Не возобновлять работу без явного сброса

## 9. Сторожевые таймеры

### 9.1 IWDG

Параметры из VESC:

```c
IWDG_SetPrescaler(IWDG_Prescaler_4);   // LSI/4
IWDG_SetReload(140);                    // t ≈ 12 мс при LSI=47 кГц (макс.)
```

Обоснование: поток таймаута работает каждые 10 мс. Запас 20% → 12 мс.
При минимальном LSI (17 кГц) IWDG сбрасывается каждые ~33 мс — это допустимо.

**Правило:** кормить IWDG только из гарантированно рабочего кода. В VESC — из потока
таймаута (`timeout_thread`), который контролирует `feed_counter[]` от разных потоков.

### 9.2 Программный таймаут управляющего канала

`timeout_feed_WDT(THREAD_MCPWM)` вызывается из ADC ISR при каждом цикле FOC.
Если FOC-цикл зависает, `timeout_thread` обнаруживает замороженный счётчик и применяет
тормозной ток `timeout_brake_current` (по умолчанию 0 А — полное отключение).

Конфигурация: `timeout_configure(1000 мс, brake_current, kill_sw_mode)`.

## 10. Архитектура RTOS-задач

### 10.1 Задачи VESC

| Задача | Приоритет | Функция |
|---|---|---|
| ADC ISR | IRQ (выше всех) | FOC-цикл |
| `fault_stop_thread` | HIGHPRIO-3 | Немедленная реакция на fault |
| `timeout_thread` | NORMALPRIO | IWDG + программный таймаут |
| `timer_thread` | NORMALPRIO | Термозащита, temp compensation |
| `hfi_thread` | NORMALPRIO | Расчёт HFI-позиции |
| `pid_thread` | NORMALPRIO | Внешний контур PID (скорость/позиция) |
| `sample_send_thread` | NORMALPRIO-1 | Отправка осциллограмм |

### 10.2 Рекомендации для robot-ace

- ADC ISR не должен ждать мьютексов — только атомарные записи в volatile-переменные
- Задача fault_stop — первая реагирующая; самый высокий приоритет среди задач
- PID по скорости/позиции — отдельная задача, ниже приоритетом чем fault
- Задачи управления моторов разбудить через прямое уведомление (`xTaskNotifyFromISR`)
  или очередь с глубиной 1

### 10.3 Критические секции

```c
SYS_CRITICAL_ON();   // taskENTER_CRITICAL()
// ... изменение разделяемых переменных
SYS_CRITICAL_OFF();  // taskEXIT_CRITICAL()
```

Не использовать критические секции внутри ISR — там использовать `taskENTER_CRITICAL_FROM_ISR`.

## 11. Последовательность инициализации

```
1. Инициализация платформы (тактирование, GPIO, UART, I2C, SPI)
2. Инициализация ADC + DMA (каналы фазных токов, Vbus, NTC)
3. Инициализация TIM1 (PWM 3-фазный, центрально-симметр., dead time, BRK)
4. Инициализация TIM2 (триггер ADC)
5. Все PWM в DISABLED состоянии — НЕ включать MOE до конца инициализации
6. Инициализация энкодера (AS5600 по I2C): проверить наличие магнита
7. Запуск ADC с DMA
8. DC-калибровка смещений (mcpwm_foc_dc_cal): мотор неподвижен, ток = 0
9. Проверить: mcpwm_foc_is_dccal_done() == true
10. Запуск IWDG
11. Создание FreeRTOS-задач
12. Запуск планировщика (vTaskStartScheduler)
--- Далее в задачах ---
13. Определение параметров мотора (R, L): mcpwm_foc_measure_res_ind()
14. Определение offset энкодера: mcpwm_foc_encoder_detect()
15. Переход в рабочий режим
```

## 12. Критические правила (итог)

1. **Мёртвое время — всегда.** Без него сквозной ток уничтожает транзисторы за микросекунды.
2. **При любой аварии — stop_pwm_hw() немедленно.** Нет исключений.
3. **Никакого управления без DC-калибровки.** Проверять `mcpwm_foc_is_dccal_done()`.
4. **CCR обновлять атомарно** через UDIS. Нельзя писать CCR1–CCR3 по отдельности.
5. **COM-событие обязательно** при смене режима OCxM (stop/start_pwm_hw).
6. **BRK с AutomaticOutput_Disable.** Автовосстановление PWM после аварии = опасность.
7. **IWDG кормить только из « живого» кода.** Не кормить безусловно — теряется смысл.
8. **FOC-цикл в ISR должен кормить программный WDT.** Зависание FOC = немедленный тормоз.
9. **Duty cycle: [MIN_DUTY, MAX_DUTY].** Ниже минимума нет стабильного замера тока.
10. **Full Brake только при малых скоростях** (`|RPM| < L_CURR_MAX_RPM_FBRAKE`).
11. **Fault = защёлка.** Не возобновлять выход не без явного сброса и анализа причины.
12. **ISR без мьютексов.** Только volatile-переменные и атомарные операции.
